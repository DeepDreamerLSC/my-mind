# my-mind 轻量闭环目标模式

## 目标

本地 Markdown 保持为知识可信源；OpenClaw/飞书是唯一日常前台；Codex 负责后台解析、门禁和回写。用户日常只查看一个最多 3 项的“今日动作”。

## 交付状态

交付状态固定为：

1. `prepared`：前台推送稿已生成。
2. `published`：飞书页面已准备并可访问。
3. `sent`：OpenClaw 返回真实发送回执、消息 ID 或显式幂等确认。
4. `feedback_received`：用户反馈已追加到反馈队列。
5. `applied`：反馈已成功回写或目标动作已完成。

禁止根据文件生成、页面准备或历史字段推断 `sent`。旧版没有真实发送证据的条目保持 `delivery_stage` 为空，并用 `legacy_delivery: unknown` 表示交付未知。

## 今日动作

固定视图为：

- `85_运行记录/后台总览/今日动作.json`
- `85_运行记录/后台总览/今日动作.md`

每次只输出 `阅读`、`确认`、`补充判断/核验`、`暂无动作` 之一；来源去重，最多 3 项。相同输入重复刷新不得产生内容变化。

## 库存门禁

自动前沿情报入箱前检查：未读大于 10、`sent` 待反馈大于 3、待确认大于 5。任一条件超限时停止自动入箱，用户主动入箱不受影响。

## 写入边界

- `prepared`：推送状态与本次推送稿。
- `published`：推送状态与发布记录。
- `sent`：推送状态与可选触达记录。
- `feedback_received`：反馈队列与推送状态。
- `applied`：反馈队列、推送状态、来源、可选候选、待确认视图，最多 5 个文件。
- 今日动作刷新：固定 JSON 与 Markdown，共 2 个文件。

## Rollout 边界

本地实现和测试不得修改 live automation，不得执行真实飞书发送、移动、删除或批量写入。外部发送和自动化恢复必须在本地测试通过后使用单独 rollout 授权，并在无回执时停在 `published`。
