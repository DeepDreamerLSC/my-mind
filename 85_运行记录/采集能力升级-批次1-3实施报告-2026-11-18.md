## 2. 环境部署

### dtk（抖音解析/下载服务）

- 部署于 `~/.local/services/dtk`（上游 Evil0ctal/Douyin_TikTok_Download_API），docker compose 编排：`docker compose -p dtk -f docker/compose.yml up -d --wait`。
- 服务地址 `http://127.0.0.1:18600`：compose 侧端口经 `docker/.env` 覆写（`DTK_BIND_HOST=127.0.0.1`、`DTK_BIND_PORT=18600`），只绑本机回环，不对局域网暴露。
- 身份池：`--profile browser` 启用浏览器自动铸造（browser-rpc 无头浏览器容器模拟真实浏览器会话，自动生成新平台身份补充进池）；不可用时可从控制台 Identities 手工导入 cookies。

### XHS-Downloader（小红书解析/下载服务）

- 部署于 `~/.local/services/xhs-downloader`（上游 JoeanAmier/XHS-Downloader，GPL-3.0，只以独立进程/HTTP API 调用，不复制其代码进仓库）。
- 服务地址 `http://127.0.0.1:18601`：上游 API 模式硬编码 `0.0.0.0:5556` 且不改上游代码，故用仓库外启动器 `~/.local/services/run-xhs-api.py` 调用其 `main.api_server(host="127.0.0.1", port=18601)` 绑回环；`nohup` 后台运行，日志 `~/.local/services/logs/xhs-api.log`。

### 凭据（只记位置与键名，不含任何值）

- `~/.config/my-mind/dtk.json`（chmod 600，不进仓库）。键名：`base_url`、`api_key`、`auth_header`、`admin_user`、`admin_password`、`scopes`、`secret_key_location`、`project.{compose_file, compose_project, env_file, port_override_file}`。`secret_key_location` 只存部署机 `.env` 内 `DTK_SECRET_KEY` 的位置说明，不存密钥本身。
- `~/.config/my-mind/xhs.json`（chmod 600，不进仓库）。键名：`base_url`、`bearer_token`、`auth.{header, mechanism, regenerate_command}`、`cookie.{global_settings_file, note, per_request}`、`service`、`restart_command`、`stop_command`、`probe`、`installed_at`。
- 设计稿原规划的单一 `collect.json` 实际拆为上述两文件，避免并行写冲突；README 按实际文件记录。

### 关键机制

1. **解析链回退顺序**（两平台一致）：yt-dlp 直抓 → 公开页 HTML 补充基础信息 → 自建服务（dtk / XHS-Downloader）兜底补全作品信息与媒体直链；各级结果写入笔记「解析说明」。实测两平台 yt-dlp 均稳定失败（抖音 `Fresh cookies needed`，小红书登录拦截页 `Unsupported URL`），由后两级完整接管，11/11 与 7/7 均为三级链形态。
2. **作品类型判定**：以自建服务返回 kind 为准（`image_album`→图文；`video`→口播视频/UI演示视频）；无 API 结果时用公开页图集标记推断；两者皆无 →「未知」并跳过转写（防图文被当视频处理）。UI 演示采用关键词启发式 `UI_DEMO_KEYWORDS`（演示/操作/教程/界面/tutorial/how to），抖音与小红书共用同一组常量；笔记「作品类型」用户可随时手动改写覆盖（设计决策 10，批次 5 前仅关键词启发式）。
3. **逐图 OCR 覆盖门禁**：图文作品逐张下载-OCR；全量 OCR 总量上限 `XHS_IMAGE_OCR_FULL_MAX_IMAGES = 20`（超限停在 N/20 并如实标注）；OCR 全覆盖 → 内容质量可推送，未全覆盖 → 需继续解析并注明「图片尚未全部处理，不能视为完整图文解析」。
4. **媒体下载-校验-删除生命周期**：媒体经自建服务下载至 `~/.cache/my-mind/media/{平台}/{content_id}/`，ffprobe 校验格式与时长后供 OCR/转写使用，处理完成删除整目录；笔记只保留作品页链接与元数据（平台媒体直链带时效签名，仅作采集证据记录）。
5. **CLI 新增参数**：`--no-extract-content`（不下载视频，视频媒体链接与时长直接取服务元数据）、`--no-image-ocr`（跳过图片下载与 OCR，文案等其余媒体信息不受影响）。

## 4. 实测验收

### 抖音（批次 2）：11/11 通过

2026-11-17 对 samples.json 中 douyin-01~11 逐条执行 `capture_link.py --no-extract-content`，随机间隔 20-40 秒：

- **作品类型 11/11**：图文 1（douyin-01）、口播视频 8、UI演示视频 2——douyin-07（AI 商单剪辑教程）、douyin-08（AI 界面去 AI 味）由关键词启发式命中，与内容实际形态相符。
- **图文 OCR**：douyin-01 逐张 OCR 1/1 全覆盖（PaddleOCR，586 字），内容质量=可推送。
- **视频 10 条**：媒体直链 10/10 已记录（douyinvod.com mp4），转写=未开始（`--no-extract-content` 预期状态），内容质量=需继续解析（门禁注明视频未转写不应进入前台推送）。
- **douyin-06 观察项（非阻断）**：28:43 长视频样本，dtk 媒体下载校验遇 `SSLEOFError` 断连；dtk API 11 次 parse 全部 200 OK，错误发生在媒体直链下载阶段（疑似 CDN 对大文件连接中断或网络抖动）；元数据、类型、时长、文案、媒体链接均正常入库，命令退出码 0。大文件（>50MB）下载偶发 SSL 断连为非确定性问题（见第 7 节）。
- **媒体生命周期**：抽查（douyin-01、douyin-06）与 11 条终检 `~/.cache/my-mind/media/douyin/` 均无残留。
- **风控**：11 条连续采集无验证码、429、账号风控类错误。

### 小红书（批次 3）：首轮 0/7 → 修复 → 复测 7/7

- **首轮 0/7 根因**：`capture_link.py` 的 `guess_platform()` 只匹配 `xhslink.com`，未覆盖 7 条样本实际短链域名 `xhslink.cn`（小红书 App 分享链真实域名之一），导致小红书专属链路整体未触发——公开页抓取、XHS-Downloader 兜底、作品类型/模态覆盖新字段、OCR 与媒体生命周期全部没有执行，验收期间服务日志 0 次 `POST /xhs/detail`。判定为代码缺陷而非环境问题的依据：xhs-01 间隔 65 秒重试结果逐字段一致；服务部署期对同款作品解析 200 OK；短链重定向正常且携带完整作品参数。该缺陷为存量代码中的**预存 bug**：38 个 mock 测试全部以 `.com` 域名构造请求，mock 层测不出真实域名，由真链路验收抓到。
- **修复**：`guess_platform()` 同时识别 `xhslink.com` 与 `xhslink.cn`（两域名均覆盖），附回归测试 `test_guess_platform_accepts_xhslink_cn_short_links`；修复后全量测试绿。
- **复测 7/7**（同日 23:43-23:48）：5 视频（口播 3 + UI演示 2）+ 2 图文，与首轮从重定向 share 参数推断的预期完全一致；分享文案 7/7 完整；5 条视频直链已记录且 ffprobe 校验全过（336/352/25/1050/420 秒与元数据一致）；xhs-07 图文 OCR 1/1 全覆盖、内容质量=可推送；xhs-06 图文 32 图超 20 张全量 OCR 上限，OCR=20/32，门禁正确拦截为需继续解析（设计内总量保护，非缺陷）；媒体缓存零残留；服务 7 次 parse 全部 200 OK，无风控错误。
- 首轮 8 条失败兜底笔记（7 样本 + 1 重试）原样保留在 00_收件箱 作失败证据，未删除。
