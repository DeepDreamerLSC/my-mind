## 2. 实现内容

### segmented_transcribe.py（长视频分段转写状态机，1575 行）

| 机制 | 实现 |
| --- | --- |
| VAD 分段 | Silero VAD 经 faster-whisper 自带 `faster_whisper.vad.get_speech_timestamps` 在既有 `~/.cache/my-mind/faster-whisper-venv` 子进程执行，**零新依赖**；≥2 秒静默视为停顿，贪心合并相邻语音为 60–180 秒转录块，块边界只落在停顿处（决策 4），块时长按块内语音时长合计计（与覆盖分子分母同口径） |
| 进度存储 | 收件箱笔记 frontmatter（`转写状态` / `转写覆盖` / `转写备注`）+ 正文末尾 HTML 注释分段清单 JSON（`<!-- my-mind:transcript-segments … -->`，每块起止秒、语音时长、done、文本、句级时间戳；frontmatter 只放汇总避免 YAML 膨胀） |
| 完整判定 | 覆盖 ≥98%（`TRANSCRIPT_COMPLETE_RATIO = 0.98`）→ 已完成，复用 capture_link 的摘要/关键点/时间线/质量门禁收尾，内容质量才允许升可推送；不足 2% 的尾块按完整判定收尾并如实注明 |
| 预算续跑 | `--budget-seconds`（默认 900，决策 11）块间检查：首块保底、预算耗尽不开新块新笔记、每块完成即回写（中断不丢进度）；零进展计数存分段清单，连续 2 次零进展 → 失败（子设计三） |
| 媒体重取 | 缓存 wav → 缓存媒体抽音频 → 按 原始链接+作品页链接 经 dtk / XHS-Downloader 重取（仅抖音/小红书）；重取失败 → 失败态 + 原因，转人工核验 |
| 模型复用 | faster-whisper 常驻子进程：模型（small / int8，同一段式）只加载一次，逐块按行 JSON 协议复用；复用失败（超时/崩溃/脏输出）自动重建再试 |
| 可靠性 | 笔记与 wav 均 tmp + `os.replace` 原子写；媒体缓存目录 `O_CREAT\|O_EXCL` 并发锁（2 小时过期死锁可抢占、3 次重试上限）；缓存 wav 用 wave 头完整性校验（帧数×位宽×声道+44 ≈ 文件大小），截断/垃圾文件删除后按缓存缺失重走媒体重取 |
| 运行证据 | 每轮自动落盘 `85_运行记录/分段转写-<时间戳>.md`（候选数、逐笔记覆盖变化、退出码），总控不代写 |

### capture_link.py 集成（+79 行）

- **超限入队**：视频时长超一段式上限（默认 360 秒）不再直接放弃，初始化分段转写队列字段（`转写状态: 未开始` / `转写覆盖: 0/0秒` / `转写备注` / 模态覆盖 `转写=未开始(分段)` / 质量门禁注明不应直接进入前台推送 + 解析说明附「长视频已进入分段转写队列」）；本命令内不开始转写（保持入箱快路径），由后台总控续跑。
- **入队限定抖音/小红书**（评审 M2）：分段执行器只支持这两平台的媒体重取，YouTube/B站/TikTok 等保持批次 4 前的「超过转写上限」干净错误，避免入队后必然失败的假告警。
- **超限跳过预下载**（评审 M5）：元数据时长已超上限时不下载视频、不 ffprobe（媒体直链与时长取服务元数据），媒体由执行器续跑时一次性下载，消除「下载→入队→立刻删除」的双倍流量。

### backend-control 接入（总控日更）

- `backend_health_check.py` 新增 `inspect_transcript_queue`：扫描收件箱 `转写状态` 分布（未开始/进行中/已完成/失败）、进行中最近一条的覆盖与备注；dashboard 数字总览、Codex 后台应处理（待续跑建议 + 900 秒预算续跑命令）、风险区（失败条目）、建议动作四处联动；健康检查只发现队列并建议命令，不执行转写。
- `.codex/skills/backend-control/SKILL.md` 新增「长视频分段转写续跑（后台总控日更）」章节：巡检发现 → `segmented_transcribe.py --budget-seconds 900` → 执行器自动落盘运行证据 → 下次日重复查；长视频分几天跑完属预期，未完成不视为异常。

## 4. 独立评审与修复

| 级别 | 发现 | 处置 |
| --- | --- | --- |
| high（H1） | 截断 wav 会被误判为有效缓存，在其上规划分段导致部分转写被误判完成（半截文件死循环风险） | 已修复：缓存 wav 用 wave 头完整性校验（帧数×位宽×声道+44 ≈ 文件大小），截断/垃圾文件删除后按缓存缺失路径重走媒体重取；ffmpeg 抽取改 tmp + `os.replace` 原子写，写入中途被杀不再留下半截 wav |
| medium（M2） | 超限入队未限定平台，其他平台（YouTube 等）入队后执行器媒体重取必然失败 | 已修复：入队限定抖音/小红书，其他平台保持原「超过转写上限」干净错误；附平台回归测试（YouTube 超限不排队、超限无 platform 参数时从 info 推断） |
| medium（M3） | 分段清单数值字段损坏会裸抛异常/死循环 | 已修复：损坏清单转 `SegmentStateError` → 笔记标失败转人工核验，附测试 |
| medium（M4） | 笔记回写非原子（写入中断截断收件箱笔记）+ 无并发双跑防护 | 已修复：回写 tmp + `os.replace` 原子化；媒体缓存目录内 `O_CREAT\|O_EXCL` 轻量锁（2 小时过期死锁可抢占、3 次重试上限、异常路径 finally 释放），附锁行为测试 |
| medium（M5） | 超限视频「采集侧全量下载 → 入队 → 立刻删除」双倍下载 | 已修复：元数据时长超上限即跳过下载与 ffprobe，媒体由执行器续跑时一次性下载；抖音/小红书两侧生效，附测试与真实复验（0.96 秒、无预下载） |

## 5. 遗留与边界

1. **批次 5 视觉分析缓后**（决策 9）：关键帧提取 + GLM-4.6V 视觉分析待前序批次验收通过后另行启动；UI 演示作品当前仍按批次 1-3 的关键词启发式 + 门禁行为。
2. **预算为块间检查**：轮内实际耗时可略超预算（实测 149>120、253>240），且取媒体/VAD 不占预算；「完成当前块即收尾」符合设计，非超时缺陷。
3. **时间线为章节采样**：`build_transcript_timeline`（批次 3 共用构建器）取 3-8 条，末条时间戳为末章起点而非字面片尾时刻，但末章聚合文本覆盖尾块全程（实测块级首≈0:00、尾块 done 成立）；非批次 4 回归。
4. **>180 秒无停顿连续语音等分兜底**：`split_long_intervals` 把超长连续语音按 180 秒硬切，块边界落在语音内，违背决策 4「边界必须落在停顿处」字面，但无停顿可用时为唯一可行兜底，docstring 已注明。
5. **分段语言策略与一段式不同**：分段为逐块自动检测（`language=None`，长视频可能夹外语），一段式默认 zh；模型与精度一致，实测两样本语义一致，注释已如实注明。
6. **服务重启需手动拉起**：两服务均不配开机自启，重启电脑后按 README「服务重启与凭据补办」手动拉起（README 另新增 faster-whisper venv 重建步骤）。
7. **其他观察（非阻断）**：扫描序为文件名序（`小红书` < `抖音`，实测步骤预期与实现排序差异非缺陷）；「首轮缓存被系统清理」场景未自然发生（小红书重取路径已验证）。
